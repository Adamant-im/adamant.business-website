ADAMANT Node v0.11.1 — это важное обновление, направленное на повышение безопасности и надежности для операторов узлов, делегатов, пулов, обозревателей, мессенджеров и других сервисов, взаимодействующих с узлами ADAMANT. Это первый релиз с тегом в ветке v0.11; версия v0.11.0 была объединена с веткой `master`, но не получила тег, поэтому операторам, работающим на `master`, также следует обновиться.

Настоятельно рекомендуется выполнить обновление. Консенсус не меняется, миграция SQL не требуется: сериализация, подписи, порядок делегатов, вознаграждения, комиссии, высоты активации и тайминги слотов остались такими же, как в v0.10.2. Однако из-за критических изменений в HTTP API и системных требований операторам следует ознакомиться с руководством по обновлению перед началом работы.

## Перед обновлением

Теперь требуются Node.js 22.22.2+ (в рамках ветки 22.x) или 24.15.0+. Устаревшие API для форжинга и управления средой выполнения DApp были полностью удалены (GHSA-vjhq-r5fg-85cx). Форжинг теперь настраивается через параметр `forging.secret` в файле `config.json`; API DApp, работающие в режиме только для чтения, и типы транзакций DApp не затронуты. Фильтры для состояний, чатов и комнат теперь работают строго: фильтры `and:` работают ожидаемым образом, в то время как `or:`, а также ошибочные или неподдерживаемые параметры теперь отклоняются, а не игнорируются без уведомления. Параметр `keysIds` был переименован в `keyIds`. Ограничения частоты запросов (rate limits) включены по умолчанию; старые блоки `max: 0` в `config.json` по-прежнему отключают ограничения, поэтому удалите их, чтобы использовать новые настройки по умолчанию.

## Безопасность и усиление защиты

Серверная среда выполнения DApp и HTTP-контроль форжинга были полностью удалены, а не просто исправлены, что значительно сократило поверхность атаки.

Парольные фразы делегатов в `forging.secret` теперь можно опционально шифровать с помощью пароля оператора, используя AES-256-GCM с алгоритмом формирования ключа scrypt. Узел продолжает синхронизацию и обслуживание API в заблокированном состоянии, а разблокировка форжинга выполняется локально через CLI-инструмент `adm-node`. Конфигурационные файлы в открытом виде по-прежнему поддерживаются. Включены шаблоны Zabbix для отслеживания состояния блокировки и результатов работы делегата.

Добавлены ограничения частоты запросов для защиты от злоупотреблений для публичного REST, peer HTTP и WebSocket трафика с возвратом стандартного ответа `429`. В период перехода на новую версию запросы `/peer/*`, не содержащие новый заголовок ограничения частоты, не будут ограничиваться, и любой вызывающий объект может его опустить. Операторам рекомендуется добавить ограничение для `/peer/*` на уровне обратного прокси-сервера или брандмауэра, пока контроль на уровне узла не будет полностью отслежен и внедрен.

Скрипты установки и восстановления стали безопаснее: контрольные суммы снимков проверяются, завершение работы PM2 и systemd происходит корректно, а синхронизирующийся узел не перезапускается без принудительной команды. Зависимости обновлены с применением 7-дневного карантина для релизов в CI, при этом критических или умеренных уязвимостей в ходе аудита не выявлено.

## Надежность и работа сети

Узел теперь восстанавливает соединения с PostgreSQL после перезапуска базы данных, вместо того чтобы зависать. Проверки работоспособности пиров и размеры ответов ограничены, добавлена логика повторных попыток и исключения недоступных пиров. Исправлены исходящие WebSocket-соединения как для ротации пиров, так и для регрессии v0.11.0, из-за которой исходящие соединения не устанавливались вовсе. Завершение раунда ограничено высотой, а откат вознаграждений синхронизирован для каждого делегата; повтор и восстановление привели к идентичному состоянию в основной и тестовой сетях. Отдельная проблема с откатом остается открытой. Более быстрая проверка контрольных точек памяти и обновленные seed-пиры завершают работу по повышению надежности.

## API и документация

Фильтры `and:` теперь корректно учитывают `toHeight` и комбинированные условия отправителя/получателя. Документация и спецификация OpenAPI 3.2 теперь находятся в репозитории узла, поэтому код, схема и документация обновляются синхронно. Схема API опубликована по адресу https://docs.adamant.im/schema/. Разработчикам API-клиентов и инструментов следует в дальнейшем использовать исходные файлы OpenAPI из директории `openapi/` в репозитории узла.

## Как обновиться

Обновите Node.js до поддерживаемой версии, затем корректно остановите узел и дождитесь сообщения `Cleaned up successfully` — никогда не используйте `kill -9`. Переключитесь на версию v0.11.1 и выполните `npm ci --omit=dev`. Проверьте `config.json` на наличие блоков ограничения частоты, `trustProxy` и любых автоматизированных скриптов, вызывающих удаленные конечные точки. Запустите узел; при использовании зашифрованных парольных фраз выполняйте `npm run adm-node -- forging unlock` после каждого перезапуска. Проверьте `/api/node/status`, прогресс синхронизации, соединения с пирами и статус форжинга.

Перед выпуском версия v0.11.0 работала на узле в основной сети с четырьмя делегатами и зашифрованными парольными фразами более 16 часов: было создано 471 блок, ни один не был пропущен после перезапуска. Единственная специфическая проблема релиза — регрессия исходящих WebSocket — исправлена в v0.11.1.
