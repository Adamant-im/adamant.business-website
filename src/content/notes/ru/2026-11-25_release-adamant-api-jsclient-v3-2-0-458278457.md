ADAMANT API JS Client v3.2.0 — это релиз, направленный на повышение безопасности и корректности работы, согласованный с ADAMANT Node v0.11.0. Всем пользователям версий v3.0.0 и v3.1.0 следует обновиться до v3.2.0.

## Проверка публичных ключей получателей и делегатов

SDK теперь принудительно выполняет каноническую проверку 32-байтовых Ed25519-ключей, находящихся на кривой, отклоняя не-канонические, вне-кривые и ключи малого порядка (1, 2, 4 и 8) Curve25519. Также выполняется локальная проверка вывода ADM-адреса перед кэшированием или шифрованием сообщений. Метод `getPublicKey()` возвращает пустую строку без выполнения сетевого запроса для некорректных ADM-адресов, а также возвращает пустую строку без загрязнения кэша, если узел возвращает несоответствующий или поврежденный ключ. Метод `sendMessage()` локально перепроверяет ключи получателя и отклоняет невалидные или несоответствующие ключи с результатом `{success: false, errorMessage}`, а `voteForDelegate()` отклоняет ключи делегатов, не прошедшие привязку к адресу. Кэш `publicKeysCache` на базе `Map` проверяется как при записи, так и при чтении, а зависящие от сети кэши делегатов (`byAddress`, `byUsername`) изолированы для каждого экземпляра `AdamantApi`.

## Исправление KVS и фильтра чатов

Методы `getKVS()`, `getChatTransactions()`, `getChats()` и `getChatMessages()` теперь передают имена фильтров в простом виде, убирая явные обертки `and: { ... }`, что соответствует задокументированному контракту узла для всех версий ADAMANT Node. Неподдерживаемые обертки `or` и ключи фильтров с префиксами `and:` или `or:` в эндпоинтах, поддерживающих только AND, отклоняются на стороне клиента с результатом `{success: false, errorMessage}` вместо отправки префиксов, которые игнорируются старыми узлами и отклоняются узлами v0.11.0+. Это было подтверждено с помощью записанного теста фикстуры `/api/states/get` в основной сети.

## Готовность узлов и фильтрация загрузчика

Узлы, сообщающие `loader.loaded: false` или `loader.syncing: true`, исключаются из списка активных узлов и WebSocket-соединений, в то время как устаревшие узлы без объекта `loader` остаются доступными. Обратный вызов `onReady` (и `api.isReady`) удерживается до тех пор, пока не будет выбран рабочий узел; проверки при запуске повторяются с экспоненциальной задержкой в 5, 10, 30 и 60 секунд. Процесс продолжается, даже если предыдущая попытка завершилась ошибкой, вместо ожидания 5-минутного цикла проверки. Если после инициализации все готовые узлы недоступны или не соответствуют `minVersion`, SDK с предупреждением переключается на совместимый с `minVersion` узел, который загружен, но синхронизируется, только если доступна информация о недавней высоте синхронизации (в пределах 10 минут) и кандидат находится не далее 25 блоков от этой высоты. Предотвращен повторный вызов `onReady` в случае ошибки, а ответы, не являющиеся объектами (например, HTML-страницы 200 maintenance, null или неполные статусы `{success: true}`), безопасно пропускаются.

## Согласование API ADAMANT Node v0.11.0, OpenAPI и KVS POST

Генерация детерминированных API DTO (`scripts/sync-api-types.mjs`) перенесена из архивированного репозитория `Adamant-im/adamant-schema` в `Adamant-im/adamant` (файл `openapi/specification/openapi.yaml` в релизном коммите v0.11.0 `50568f37dc2b7da86f44991f96c40c8edde74d67`), с чтением версий инструментов через `createRequire`. Сгенерированный файл `src/api/generated.ts` был обновлен, включая `RateLimitErrorResponseDto`, `GetKVSRequestBody` и актуальные ссылки на `https://docs.adamant.im/`. Типы опций эндпоинтов (`ChatroomsOptions`, новые `ChatTransactionsOptions` и `KVSOptions`) приведены в соответствие со строгой валидацией фильтров ADAMANT Node v0.11.0: фильтр `toHeight` обязателен для `/api/chats/get` и `/api/states/get`, а фильтры высоты/диапазона исключены из `/api/chatrooms/*`. Поле `ChatroomsOptions.userId` помечено как устаревшее и удаляется во время выполнения для `/api/chatrooms/*` с выводом однократного предупреждения, чтобы старые вызовы не вызывали ошибок валидации на узлах v0.11.0+. Добавлена поддержка `POST /api/states/get` через `api.getKVS(options, {method: 'POST'})` для запросов с большим количеством `keyIds` или `senderIds` с полным идемпотентным отказоустойчивым чтением, аналогичным `GET`.

## Устойчивость к HTTP 429 и отказоустойчивость

SDK фиксирует `targetNode` перед каждым запросом, чтобы параллельные сбои не переключали `this.node` обратно на неисправный узел. При получении HTTP 429 от нескольких узлов SDK немедленно переключается на другой кэшированный синхронизированный узел без дополнительных проверок `/api/node/status`, пропускает проверки здоровья при 429-ошибках на одном узле и обрабатывает 429 в `checkNode()` отдельно от офлайн-узлов. Параллельные проверки `updateNodes()` дедуплицируются через промис, а запланированная проверка принудительно переводится в режим аварийного переключения, если запрос сообщает о сбое узла. SDK исключает `failedNode` из наборов из 2 и более синхронизированных узлов и отслеживает время ожидания 429 для каждого узла (`rateLimitedUntil`, максимум 60 секунд), чтобы принудительные и плановые проверки избегали ограниченных по скорости узлов до истечения времени ожидания. SDK парсит заголовки `Retry-After`, `RateLimit-Reset` и `RateLimit-Scope`, выполняет немедленное переключение для идемпотентных операций чтения (`GET` и `POST /api/states/get`) при наличии другого синхронизированного узла или соблюдает ограниченную задержку с джиттером до 10 секунд на одном узле без зацикливания. Дополнительные метаданные `status`, `retryAfterMs` и `rateLimitScope` теперь доступны в результатах ошибок HTTP 429 в `AdamantApiResult`, при этом записи `POST` строго не повторяются.

## Обновление безопасности зависимостей и 7-дневный карантин

Релиз обеспечивает соблюдение `minimumReleaseAge: 10080` (7 дней) и явные настройки `allowBuilds` (`'@parcel/watcher': false`, `esbuild: true`, `unrs-resolver: true`) в `pnpm-workspace.yaml` без исключений по возрасту релиза. Прямые и транзитивные зависимости были обновлены с учетом 7-дневного порога, включая axios, bitcoinjs-lib, tiny-secp256k1, pbkdf2, socket.io-client, bip39, ecpair, semver, @redocly/cli, eslint, jest, prettier и swagger-typescript-api, что сократило количество замечаний аудита с 20 до 0. Публикация выполняется через GitHub Actions npm Trusted Publishing с подтверждением сборки.

## Валидация

Проверено на Node.js v24.19.0 и pnpm 11.13.1. Полный набор тестов (`pnpm test`) включает 20 наборов и 333 теста со 100% покрытием функций, проверка `gts lint` пройдена. Типы API соответствуют указанным коммитам ADAMANT и adamant-wallets. Документация TypeDoc и VitePress успешно собрана. Тесты пакетов для ESM, CommonJS, живых потребителей, подпутей пакетов и объявлений TypeScript пройдены. Аудит безопасности показывает 0 уязвимостей, все 893 заблокированных пакета имеют проверенные подписи.

### Breaking changes

Функции `encodeMessage()` и `decodeMessage()` теперь выбрасывают ошибку `invalid key` для не-канонических, вне-кривых и ключей малого порядка Ed25519 (1, 2, 4 и 8). Легитимные ключи основной сети это не затрагивает. Метод `getPublicKey()` возвращает пустую строку без сетевого запроса для некорректных ADM-адресов, а также возвращает пустую строку, если ключ узла не выводит адрес. Метод `sendMessage()` отклоняет таких получателей с результатом `{success: false, errorMessage}`, а `voteForDelegate()` отклоняет ключи делегатов, не прошедшие привязку к адресу.

Изменения в сужении типов запросов TypeScript: `ChatroomsOptions` и `KVSOptions` больше не наследуют неподдерживаемые поля `TransactionQueryParameters`, которые отклоняются ADAMANT Node v0.11.0. Метод `getChatTransactions()` теперь использует `ChatTransactionsOptions` — надмножество `ChatroomsOptions`, сохраняющее `fromHeight`, `toHeight`, `inId` и `isIn`. `TransactionQueryParameters` остается экспортированным без изменений.

Вызов `transformTransactionQuery(query, 'states' | 'chats' | 'chatrooms')` напрямую с оберткой `or` или ключами фильтров с префиксами `and:` или `or:` теперь выбрасывает `Error` с сообщением `badParameter`, тогда как клиентские методы `AdamantApi` возвращают `{success: false, errorMessage}`.

Фильтр `toHeight` в `getKVS()` и `getChatTransactions()` принудительно применяется только ADAMANT Node v0.11.0+. Старые узлы молча игнорируют `toHeight` и возвращают более новые записи с `success: true`, поэтому вызывающим сторонам, полагающимся на верхнюю границу высоты, следует установить `minVersion: '0.11.0'`.

Поле `userId` в `/api/chatrooms/*` помечено как устаревшее в `ChatroomsOptions` и удаляется во время выполнения с выводом предупреждения. Вызывающим сторонам следует передавать адрес аккаунта только в качестве аргумента пути URL в `getChats(address)` или `getChatMessages(address1, address2)`.

При `checkHealthAtStartup: true`, `onReady` теперь ожидает, а `api.isReady` остается `false` до тех пор, пока не будет выбран рабочий, загруженный и несинхронизирующийся узел, с повторными попытками проверки с задержками 5, 10, 30 и 60 секунд.

Дополнительные поля `status`, `retryAfterMs` и `rateLimitScope` добавлены в вариант `success: false` результата `AdamantApiResult`, если запрос завершается ошибкой HTTP 429.

Байтовая структура транзакций, хеши, ID, подписи, шифрование, вывод кошелька и корневые экспорты остались без изменений.
