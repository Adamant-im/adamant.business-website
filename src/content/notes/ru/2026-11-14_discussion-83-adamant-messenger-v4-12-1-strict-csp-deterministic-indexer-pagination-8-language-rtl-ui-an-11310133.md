ADAMANT Messenger PWA `v4.12.1` базируется на версии `v4.12.0` (`dfe094d3`) и включает изменения из ветки `master` (`074db965`), охватывающие 69 коммитов, 12 объединенных pull-реквестов и 14 закрытых задач. Помимо функциональных улучшений, этот релиз сосредоточен на верифицируемой передаче данных, усилении среды выполнения, детерминированной пагинации узлов и индексаторов в децентрализованной инфраструктуре, полной поддержке восьми языков с RTL-интерфейсом для арабского языка, а также на прозрачности происхождения сборок для веб-версии, десктопа и Android.

## Строгий CSP, Web3-валидация без eval и общие заголовки безопасности

Единый контракт заголовков безопасности (`PWA_SECURITY_HEADERS` в `vite-config/plugins/cspHardeningPlugin.ts`) теперь определяет единственный источник истины, применяемый во всех сборках — `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` и `X-XSS-Protection: 0`. Эти параметры дублируются в заголовках `vercel.json` и конфигурационных файлах nginx. Web3 ABI и валидация переведены на Zod 4 с использованием `config({ jitless: true })` для `web3-validator` и `abitype` для `web3-eth-abi`, что исключает точки входа компилятора, в то время как плагин CSP расширяет защиту производственного бандла от использования `eval` и псевдонимов `Function` во время выполнения.

Усиление цепочки поставок включает использование `.npmrc` с минимальным возрастом релиза зависимостей в семь дней, скрипт проверки возраста релизов, ограничения Dependabot, очистку производственных сборок Electron и исключение учетных данных и артефактов Playwright. Проверки развертывания в реальном времени (`cspDeployments.env.spec.ts`, `tests/e2e/production-csp.live.spec.ts`) подтверждают наличие заголовков и работу скриптов на экране входа без нарушений CSP в производственной среде, среде разработки, GitHub Pages и Surge.

## Минимальные версии узлов, ограниченные запросы PostgREST и пагинация на одном узле

Минимальная версия ADM API повышена до `0.10.0` для основной сети, тестовой сети и Tor. Минимальная версия узла IPFS теперь явно считывается из `ipfsService.minVersion` (`0.1.0`) вместо использования общего значения для всех сервисов. Резервные IP-адреса узлов синхронизируются через реестр `adamant-wallets`.

Улучшена работа прямых переводов ADM в реальном времени: схема заменяет `withoutDirectTransfers` на целочисленные перечисления, WebSocket-соединения устанавливаются сразу после разблокировки с подпиской на типы транзакций чата `[0, 8]`, а статус перевода синхронизируется между превью чата, списком транзакций и компонентами карточки перевода.

Запросы к индексатору ETH через `EthIndexerClient.ts` теперь принудительно ограничиваются параметром `limit` в каждом запросе `/ethtxs` (по умолчанию 25). Поиск нативных ETH разделен на два ограниченных индексированных запроса, которые объединяются и дедуплицируются на стороне клиента по `txhash`. Также добавлен `getTimestampGroup` для разрешения границ с одинаковыми временными метками. Механизмы пагинации для BTC, DOGE и DASH теперь привязаны к одному индексатору, что предотвращает распределение адреса между операторами. Состояние модуля при сохранении очищает кэшированные транзакции и сбрасывает сессионные курсоры пагинации, предотвращая их рассинхронизацию.

## Идентификация сборки, резервный HTTP IPFS multihash и изолированные сетевые конфигурации

Плагин информации о сборке (`virtual:adamant-build-info`) отображает в диалоговом окне очищенные данные: `version`, `branch`, `commit`, `prNumber`, `author`, `buildDate` и `isTestnet`. Добавлено действие Service Worker «Принудительное обновление», которое очищает CacheStorage, сохраняя при этом учетные данные пользователя и зашифрованное состояние IndexedDB. Сборки для тестовой сети отображают явные значки `TESTNET`.

Для контекстов с обычным HTTP, таких как зеркала `.onion`, где `crypto.subtle` недоступен, резервный механизм вложений IPFS использует вычисление multihash SHA-256 через `@noble/hashes`. Сетевые конфигурации объединены в `src/config/mainnet.json` и предоставляются через виртуальный модуль, поэтому неподдерживаемые режимы Vite или утечки конфигураций между сетями приводят к ошибке на этапе сборки.

## Поддержка восьми языков и полноценный RTL для арабского языка

В этот релиз добавлены переводы на испанский, французский, японский и арабский языки, завершен аудит для немецкого, русского и упрощенного китайского. Все восемь файлов локализации приведены к полному соответствию ключей (418 ключей на локаль). Функция `applyLocale()` синхронизирует `vue-i18n`, `dayjs`, локали Vuetify, `dir` и `lang`, добавляет правила множественного числа для арабского, французского и русского языков (для чисел больше 100), выбирает цифры `ar-u-nu-latn` для арабских дат и определяет исходный язык локально через `navigator.languages`.

Полноценная RTL-верстка для арабского языка включена через `rtl: { ar: true }` в Vuetify, зеркальное отображение стрелок навигации через компонент направленных иконок, использование логических свойств CSS во всех представлениях и атрибут `dir="auto"` для сообщений пользователей (при принудительном LTR для парольных фраз). Регрессионные тесты (`RtlUiContract.spec.js`, `chat-rtl-layout-regression.spec.ts`) защищают верстку от будущих поломок.

## Упаковка и примечания к платформам

Версии Android обновлены до `compileSdkVersion` и `targetSdkVersion` 36, `minSdkVersion` повышена до 24 (Android 7.0+). Также обновлены AGP до 8.13.0, Gradle до 8.14.3 и Cordova Android до 14.0.1 (`versionCode` 41201).

На macOS компания Apple заблокировала аккаунт разработчика, поэтому нотаризация через CI временно отключена. Десктопные установщики `.dmg` (x64, arm64, universal) по-прежнему подписаны Developer ID и могут быть установлены через «Системные настройки» → «Конфиденциальность и безопасность» → «Открыть в любом случае» после первой попытки запуска. Кнопка App Store для iOS на сайте adamant.im временно неактивна, рядом размещено соответствующее уведомление.
