cryptofoundry представляет обзор adamant-api v3.2.0 — официального SDK на TypeScript и Node.js для блокчейна ADAMANT, разработанного с учетом особенностей ADAMANT Node v0.11.0.

Разработка децентрализованных приложений, торговых ботов, обозревателей или платежных интеграций напрямую через HTTP-запросы к блокчейну требует постоянного решения одних и тех же задач: выбора синхронизированных узлов, повтора запросов при кратковременных сбоях без дублирования транзакций, шифрования сообщений через NaCl, формирования детерминированных подписей и поддержания актуальности TypeScript DTO в соответствии с обновлениями узлов. Данный SDK решает эти задачи «из коробки», обеспечивая отказоустойчивость без лишнего кода: достаточно передать список независимых HTTPS-узлов, и SDK будет отслеживать их состояние, проверять высоту синхронизации, исключать устаревшие или загружающиеся узлы и автоматически переключаться на резервные. Также поддерживаются модульный импорт, полная безопасность типов TypeScript с DTO, сгенерированными на основе официальной спецификации ADAMANT Node OpenAPI 3.2, и подписки Socket.IO с автоматическим восстановлением соединения.

### Локальная проверка открытых ключей получателя и делегата

Перед шифрованием сообщения или голосованием за делегата версия v3.2.0 локально проверяет, является ли каждый Ed25519 открытый ключ, полученный от узла, каноническим 32-байтовым ключом на кривой (не малого порядка), и криптографически вычисляет соответствующий ADM-адрес. Некорректные ключи, ключи вне кривой, ключи малого порядка (1, 2, 4 и 8) или несовпадающие ключи отклоняются до этапа кэширования или шифрования, а кэши делегатов изолируются для каждого экземпляра `AdamantApi`.

### Исправление критических ошибок безопасности в KVS и запросах чатов

В версиях v3.0.0 и v3.1.0 методы `getKVS()`, `getChatTransactions()`, `getChats()` и `getChatMessages()` отправляли фильтры с префиксом `and:`, которые узлы версии ниже v0.11.0 игнорировали, возвращая `success: true` вместе с нефильтрованными данными. В v3.2.0 эти методы всегда отправляют имена фильтров в явном виде (разворачивая обертки `and: { ... }`) и отклоняют неподдерживаемые обертки `and:` и префиксы ключей на стороне клиента. Всем приложениям версии 3.x, работающим с KVS или данными чатов, рекомендуется обновиться до v3.2.0.

### Устойчивая обработка HTTP 429 для Node v0.11.0

В ADAMANT Node v0.11.0 по умолчанию включены лимиты защиты от злоупотреблений для HTTP и WebSocket. При получении ошибки HTTP 429 идемпотентные операции чтения (GET и POST `/api/states/get`) немедленно переключаются на другой кэшированный синхронизированный узел, в то время как ограниченный узел переходит в режим ожидания (до 60 секунд), чтобы проверки состояния не приводили к немедленному повторному обращению к нему. Параллельные запросы к узлу с исчерпанным лимитом используют единую дедуплицированную проверку состояния вместо перегрузки `/api/node/status` или постоянного переключения активного узла. При работе с одним узлом или если время сброса лимита превышает 10-секундный интервал ожидания SDK, `AdamantApiResult` теперь предоставляет дополнительные поля `status`, `retryAfterMs` и `rateLimitScope`, позволяющие ботам корректно планировать повторные запросы. POST-запросы на публикацию транзакций никогда не повторяются автоматически после получения ответа HTTP.

### Улучшенная готовность к запуску

Сервисы, запускаемые одновременно с локальным узлом, часто получали событие `onReady` в момент, когда узел еще загружал таблицы в память или синхронизировался с блокчейном. В v3.2.0 узлы, сообщающие `loader.loaded: false` или `loader.syncing: true`, исключаются из выбора для API и WebSocket. Событие `onReady` (и `api.isReady`) ожидает готовности с экспоненциальной задержкой (5с, 10с, 30с, 60с), пока узел не станет пригоден для выполнения запросов. Инициализированные клиенты также имеют механизм резервного переключения на синхронизирующийся узел, если все полностью синхронизированные узлы недоступны.

### POST /api/states/get и строгая типизация v0.11.0

Чтобы запрашивать десятки или сотни ключей KVS или адресов отправителей, не превышая лимит длины URL, передайте `{method: 'POST'}` в `getKVS()`:

```js
const response = await api.getKVS(
  {
    senderIds: ['U16655734187932477074', 'U15423595369615486571'],
    keyIds: ['eth:address', 'btc:address', 'doge:address'],
    toHeight: 55_000_000,
  },
  {method: 'POST'},
);
```

Интерфейсы TypeScript (`ChatroomsOptions`, `ChatTransactionsOptions` и `KVSOptions`) теперь соответствуют строгой валидации запросов в ADAMANT Node v0.11.0, поэтому неподдерживаемые поля выявляются на этапе компиляции, а генератор OpenAPI теперь синхронизируется напрямую с `Adamant-im/adamant`.

### Безопасность цепочки поставок и 7-дневный карантин

В соответствии с политикой безопасности ADAMANT, представленной в Node v0.11.0, adamant-api теперь обеспечивает 7-дневный карантин для новых релизов (`minimumReleaseAge: 10080` в `pnpm-workspace.yaml`), ограничивает выполнение скриптов жизненного цикла зависимостей через `allowBuilds`, поставляется без уязвимостей (согласно `pnpm audit`) и публикуется в npm с использованием механизма доверенной публикации GitHub Actions.

```
npm install adamant-api@3.2.0
```
