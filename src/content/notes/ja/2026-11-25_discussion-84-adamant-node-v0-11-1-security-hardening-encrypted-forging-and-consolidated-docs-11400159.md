ADAMANT Node v0.11.1は、ノード運営者、デリゲート、プール運営者、エクスプローラー、メッセンジャー、およびADAMANTノードと通信するその他のサービスにとって、セキュリティと信頼性を大幅に向上させる重要なリリースです。本バージョンはv0.11ラインの最初のタグ付きリリースとなります。v0.11.0は`master`ブランチにマージされていましたがタグ付けされていなかったため、`master`から運用している運営者もアップグレードが必要です。

アップグレードを強く推奨します。コンセンサスのフォークやSQLのマイグレーションは発生しません。シリアライズ、署名、デリゲートの順序、報酬、手数料、アクティベーションの高さ、スロットのタイミングはv0.10.2から変更ありません。ただし、HTTP APIの破壊的変更およびランタイム要件の変更があるため、運営者はアップグレードガイドを確認してから作業を進めてください。

## アップグレードの前に

Node.js 22.22.2以降（22.x系）または24.15.0以降が必須となりました。レガシーなフォージングおよびDAppランタイム制御APIは完全に削除されました（GHSA-vjhq-r5fg-85cx）。フォージングは`config.json`内の`forging.secret`を通じて設定するようになりました。読み取り専用のDApp APIおよびDAppトランザクションタイプには影響ありません。状態、チャット、チャットルームに対するフィルタは厳格化されました。`and:`フィルタは期待通り動作しますが、`or:`やスペルミス、サポートされていないパラメータは無視されず、拒否されるようになります。`keysIds`パラメータは`keyIds`に名称変更されました。レート制限はデフォルトで有効です。`config.json`内の古い`max: 0`制限ブロックは制限を無効化し続けるため、新しいデフォルト設定を採用する場合は削除してください。

## セキュリティと強化

サーバーサイドのDApp実行領域およびHTTPフォージング制御は、パッチ適用ではなく完全に削除され、攻撃対象領域が大幅に縮小されました。

`forging.secret`内のデリゲートパスフレーズは、scryptキー導出を用いたAES-256-GCMにより、運営者のパスワードで暗号化できるようになりました。ノードはロック状態でも同期やAPIの提供を継続し、フォージングのロック解除は`adm-node` CLIを使用してローカルで行います。プレーンテキストのconfigも引き続き使用可能です。ロック状態およびデリゲートの成果を確認するためのZabbixテンプレートが同梱されています。

パブリックREST、ピアHTTP、およびWebSocketトラフィックに対して、一貫した`429`応答を返す不正利用防止レート制限が追加されました。混在バージョン運用の移行期間中は、新しいレート制限ヘッダーのない`/peer/*`リクエストはスロットリングされず、どの呼び出し元も省略可能です。ノード内での強制適用が追跡・実装されるまでは、運営者はリバースプロキシやファイアウォールで`/peer/*`に対する制限を追加してください。

インストールおよび修復スクリプトの安全性が向上しました。スナップショットのチェックサム検証、PM2およびsystemdによる正常なシャットダウン設定が行われ、同期中のノードは強制されない限り再起動されません。依存関係はCIで7日間のリリース経過期間を設けて更新され、中程度以上の監査指摘事項がないことを確認しています。

## 信頼性とネットワーク

ノードは、データベース再起動後にPostgreSQL接続がスタックせず、復旧するようになりました。ピアの健全性チェックと応答サイズには制限が設けられ、到達不能なピアに対してはバックオフと排除が行われます。アウトバウンドのWebSocket接続は、ピアのローテーションおよびv0.11.0で発生していたアウトバウンド接続が全く行われないリグレッションの両方が修正されました。ラウンドの決済は高さ（height）によって制限され、報酬のロールバックはデリゲートごとに調整されています。リプレイとリカバリにより、メインネットとテストネットで同一の状態が生成されることが確認されました。ロールバックに関する別の問題は引き続き調査中です。より高速なメモリチェックポイントガードクエリと更新されたシードピアにより、信頼性がさらに向上しています。

## APIとドキュメント

`and:`フィルタは、`toHeight`および送信者/受信者の組み合わせ条件を正しく考慮するようになりました。ドキュメントおよびOpenAPI 3.2仕様はノードリポジトリ内に配置されたため、コード、スキーマ、ドキュメントが同期して変更されます。APIスキーマは https://docs.adamant.im/schema/ で公開されています。APIクライアントやツールの開発者は、今後はノードリポジトリ内の`openapi/`ディレクトリからOpenAPIソースを取得してください。

## アップグレード方法

Node.jsをサポートされているバージョンに更新し、ノードを正常に停止して`Cleaned up successfully`と表示されるのを待ってください（`kill -9`は絶対に使用しないでください）。v0.11.1をチェックアウトし、`npm ci --omit=dev`を実行します。`config.json`のレート制限ブロック、`trustProxy`、および削除されたエンドポイントを呼び出す自動化スクリプトを確認してください。ノードを開始します。パスフレーズを暗号化している場合は、再起動のたびに`npm run adm-node -- forging unlock`を実行してください。`/api/node/status`、同期の進捗、ピア接続、およびフォージングの状態を確認してください。

リリース前、v0.11.0は4つのデリゲートと暗号化パスフレーズを使用してメインネットノードで16時間以上稼働し、471ブロックをフォージングしましたが、再起動後の取りこぼしはありませんでした。リリース固有の問題として発見されたアウトバウンドWebSocketのリグレッションは、v0.11.1で修正済みです。
