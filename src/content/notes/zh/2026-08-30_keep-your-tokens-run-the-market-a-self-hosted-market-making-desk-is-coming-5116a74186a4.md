如果您发行了代币，您一定熟悉这种推销：做市商会“打理订单簿”、收窄点差、制造交易量——您只需将代币和报价资产交给他们，然后静候佳音。这正是最令您不安的部分。这些代币是您的流动性、您的金库，也是您上市故事的核心。一旦它们离开您的钱包，您就不再是在进行做市，而是在租赁一个“黑盒”。您无法查看哪些订单属于自己，无法在凌晨三点停止机器人，也无法向合作伙伴证明资产仍归您所有。

自托管、自主可控的做市模式则完全相反：您保留代币、API 密钥和整个流程。软件就在您的交易所账户旁运行。没有任何资产由其他司法管辖区的做市商托管。

这种模式已在 [ADAMANT Market-Making Software](https://marketmaking.app) 中实现，为 CEX 上市提供自托管流动性。它在您的账户上挂单并管理做市流程——包括点差、深度、阶梯、成交量和价格区间。您只需安装它，指向您的 API 密钥，代币就永远不会离开您拥有的交易所钱包。目前这种控制权虽然真实有效，但仍属于高级用户循环：ADAMANT Messenger、Telegram 和 CLI。一条指令，一条文本回复。对于您日常维护的单个交易对尚可，但对于多个交易对的集群，或者当您需要一眼查看订单簿、K 线、库存以及过去十二小时的情况时，这种方式就显得力不从心了。

这正是 cryptofoundry 一直在填补的空白。

## 为永不触碰您代币的软件打造的 Web 工作台

该项目正在构建一个私有的、自托管的 WebUI：浏览器中的一个地址，即可管理多个标签页中的机器人。您以操作员身份登录，选择一个交易对，即可获得市场界面、参数表单、指令和日志——而浏览器本身从不与交易所直接通信。这种架构刻意追求“平庸”。WebUI 不会持有交易所密钥，也不会在云端下单。每一个图表、余额查询和撤单操作都通过您机器人的 API 进行。机器人始终是唯一与交易所交互的进程。

登录功能位于您的控制台上，而不是交易所或第三方做市商处。每个机器人仅验证已签名的令牌。这是场景 A：您运行控制台（通常位于您控制的机器上，并在 HTTPS 保护之下），通过 URL 添加每个机器人，并与集群共享一个 HMAC 密钥。一个 WebUI，多个实例——无论是 Binance、Bybit、Gate、BiFinance 还是您实际上市的任何平台。托管订阅模式（场景 B：出站中继，机器人配置中包含许可证，无入站机器人端口）是后续产品。规则始终不变：代币保留在您的交易所账户中。

## 市场，而非聊天记录

打开一个机器人标签页，您就进入了一个做市工作台：带有您订单绘制的 K 线图、包含点差、24 小时区间和成交量的实时订单簿、以代币和美元计价的基础/报价资产库存，以及在需要时手动调整的限价单。点击订单簿，即可自动填充方向、价格和数量。撤单操作会发送订单 ID、市场和方向；该行随即从表格中消失。您通过自己的机器人，直接查看自己的账户。

![Market view](/images/engineering-notes/medium/5116a74186a4/002-a2f1096b3e.webp)

*市场视图。K 线、订单簿、美元库存和下单功能——多机器人集群中的一个标签页。这依然是您在交易所的 API 密钥和钱包。*

## 凌晨两点也能看懂的参数

做市不仅仅是一个开关。它涉及流动性区间、价格监控、阶梯挂单、成交量和通知。WebUI 将这些功能转化为分组表单。如果某个模块未包含在此机器人构建版本中，该分组将保持锁定状态——您无需猜测哪个 `/enable` 代码对应哪个功能卡片。

“实时状况”专为拒绝彻夜守在终端前的操作员设计：提供十二小时的库存（基础资产 + 美元报价资产）和挂单组合情况。当您连接时，浏览器会自动填充柱状图。黄色小时表示质量下降；灰色表示做市已关闭。您看到的是整个夜晚的概况，而不仅仅是一个快照。

![Parameters](/images/engineering-notes/medium/5116a74186a4/003-5c8d7d7f51.webp)

*参数设置。主做市开关、12 小时实时状况、流动性、价格监控、阶梯挂单。分组与该机器人实际安装的功能保持一致。*

关于机制的说明，因为这在出现问题时至关重要：机器人会标记做市上次启动的时间，以及进程在做市开启状态下上次重启的时间。时间戳相等意味着干净的启动。如果初始化时间早于重启时间，则说明容器已重启。公共进程存活状态 (`/health`) 保持为一个微小的 `{ status, transport }` 对象，因此可访问的端口不会泄露订单簿质量。质量是单独的、经过身份验证的 `/status`。

填充、关闭、定价、TWAP、转账、提现和查询——与 Messenger 和 CLI 使用相同的处理程序，但在执行破坏性调用时会要求确认，右侧还有实时控制台。

![Commands](/images/engineering-notes/medium/5116a74186a4/004-18e42a4cf7.webp)

*指令。专为工作台设计的高级用户集：填充订单簿、关闭切片、定价、在控制台中查看机器人反馈。*

由于“是谁关掉了做市？”是一个常见问题，WebUI 中的“事件”功能提供了审计追踪——操作员与机器人、参数与指令之间的对比，并支持搜索和导出。

![Events](/images/engineering-notes/medium/5116a74186a4/005-0c6f4d12d6.webp)

*事件。发生了什么、何时发生、由谁操作：您、同事还是机器人本身。*

## 为什么这不仅仅是另一种 SaaS 做市服务

大多数“我们将为您做市”的提议都是为了优化他们自己的运营：他们需要将您的代币存入他们的账户，以便机器人进行交易。而这种模式是为了优化您的运营。托管权保留在您签发密钥的交易所账户下。机器人在您选择的地方运行——您的 VPS 或机架。WebUI 是该进程的一个窗口，而不是一个新的托管方。一个控制台即可覆盖您关心的每一个交易对。

如果上市需要第二个 API 密钥以符合自成交规则，那依然是您的第二个账户。如果您停止软件，订单仍由您撤销。如果您解雇了供应商，您无需等待代币退回，因为它们从未离开过您的账户。
