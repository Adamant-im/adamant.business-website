做市基础设施往往功能强大但操作不透明。状态分布在不同的指令中，参数散落在各处，而触发保护性停止的原因可能深埋在日志里。场景 A 的第三个 MVP 增量——私有化部署的 ADAMANT Market-Making WebUI，将浏览器从一组孤立的控件转变为一个更清晰的操作界面，为日常运营代币流动性的操作员提供支持。

全新的“每机器人仪表板”（per-bot Dashboard）是主要的着陆视图。它汇集了交易对和交易所背景信息、来自机器人 /status API 的做市状态、功能版本徽章、紧凑的 15 分钟价格图表、活动与非活动模块、可读的参数摘要、余额以及按用途分组的挂单。版本徽章（从 Basic 到 Full）源自机器人安装的功能，而非当前启用的模块。这可以防止操作员在某个模块临时禁用时误判正在管理的机器人。

![更清晰的做市指令界面：ADAMANT WebUI 场景 A-3](/images/engineering-notes/medium/867a0d568e69/002-57c6753fc6.webp)

“启动”（Start）操作现在被设计得更加中立。启动做市不再发送策略覆盖指令；机器人将保留其自身已配置的当前策略。这防止了用户界面上的点击在不知情的情况下更改了实时策略的运行模式。在市场层面，操作员可以在 OHLC 图表上看到正在形成的蜡烛图、订单簿和近期交易中的机器人订单标记、挂单叠加层、价差背景、余额以及订单输入界面。取消订单会发送精确的 { id, market, side } 请求；如果订单已消失，系统会将其视为成功结果，而非令人恐慌的错误。这区分了真正的操作异常与人类点击与已成交或已取消订单之间正常的竞态情况。

场景 A-3 将安全路径连接到了 WebUI 中。当机器人因安全原因自动停止做市或暂停阶梯交易时，浏览器会在对话框中显示机器人的通知文本，并在“参数”中反映紧急状态。安全事件会以醒目的徽章出现在“事件”面板中；挂起的阶梯交易可以从相关的事件行恢复。事件面板还记录了来自 WebUI 与机器人端来源的参数变更，显示做市状态，并可在操作时显示余额快照和变化量。这为事故调查创建了连贯的审计追踪。

![更清晰的做市指令界面：ADAMANT WebUI 场景 A-3](/images/engineering-notes/medium/867a0d568e69/003-e5260f854d.webp)

“参数”屏幕现在包含一个操作员时区的 12 小时实时情况条。它按用途汇总了库存价值和挂单名义价值，让操作员能够直观地了解风险敞口和流动性布局的演变。健康历史以小时为单位显示：降级的小时显示为黄色，而做市停止的小时显示为灰色。启动操作后，质量模型包含 10 分钟的宽限期，因此新启动的机器人不会立即根据其尚未有足够时间产生的数据进行评判。可见性应诚实地表达不确定性；“工作正常”、“降级”和“停止”比永久绿色的仪表板更有用。

![更清晰的做市指令界面：ADAMANT WebUI 场景 A-3](/images/engineering-notes/medium/867a0d568e69/004-4f86597efd.webp)

全新的仅限管理员的“配置”视图保持了操作上下文的统一：运行时、交易对以及 tradeParams_*.js 值的实时树状结构并排显示，随后是结构化的 config.json 摘要和原始 JSON 视图。配置快照经过了清理；当机器人未报告 socket 字段时，显示为 *Not included*，而省略最小交易额的交易所则表示为 *Not provided*，而不是误导性的零。

![更清晰的做市指令界面：ADAMANT WebUI 场景 A-3](/images/engineering-notes/medium/867a0d568e69/005-913c132505.webp)

当运行多个机器人时，切换标签页会清除操作员的当前位置，这会带来不便。场景 A-3 增加了更清晰的舰队外壳和注册表。每个机器人都有一个可编辑的标签和账户，并带有源自机器人 ID 和配置的有用默认值。传输方式、版本、分支和交易对余额在舰队层面可见。离线或未知的行会被置灰，而连接正常但已停止的机器人则保持可读。在界面背后，保持活跃（keep-alive）窗格在切换机器人和部分时保留垂直滚动位置和页面内状态。隐藏的窗格会读取冻结的 Redux 快照，而不是折叠为空状态，允许操作员在比较市场、检查配置后返回，而不会丢失进度。

WebUI 仍然是私有化部署。它使用 DirectHttpTransport 与机器人的 /api/v1 接口通信；浏览器和 WebUI 后端不直接连接到交易所，交易所 API 密钥也不应存放在 WebUI 中。强制性的操作员 2FA 支持电子邮件、ADAMANT 或以太坊钱包验证。技术栈使用 Vite、React 18、Chakra UI、Fastify BFF 和 SQLite 事件日志。该功能是附加的，对于尚未公开 /status 接口的旧版本机器人，会自动回退到现有的 /health 路由。实现“无策略启动”行为需要匹配的现代机器人构建版本。

场景 A（私有化部署 MVP）在其既定范围内已功能完备。下一个部署模型（场景 B）保持独立：出站中继、公共订阅 WebUI、许可令牌范围和推送市场数据均未包含在此版本中。WebUI 仍通过轮询 REST API 获取市场数据。这种分离使得现有的私有操作员工作流程在扩展信任模型之前更加清晰且易于审计。对于运行代币做市机器人的团队来说，结果是为基本操作需求提供了一个更从容的答案：一个将实时状态、控制、历史记录、配置和安全上下文连接起来，同时将交易所边界保持在机器人内部的统一界面。
