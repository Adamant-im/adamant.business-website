ADAMANT 区块链节点 v0.11.1 是针对节点运营商、代表、矿池运营商、浏览器、信使和开发者的一次重要安全与可靠性更新。此版本移除了旧版锻造和 DApp 运行时控制 API（解决了 GHSA-vjhq-r5fg-85cx 问题），增加了可选的代表锻造密码短语加密功能，启用了生产环境下的 HTTP 和 WebSocket 反滥用限制，强化了安装与修复脚本，修复了 PostgreSQL、对等节点和轮次结算的可靠性问题，并将文档和 OpenAPI 3.2 规范迁移至此仓库中。

v0.11.1 是 v0.11 系列的首个正式发布版本。v0.11.0 代码已于 2026-11-23 合并至 master 分支但未打标签。v0.11.1 在此基础上增加了一项网络修复，因此已从 master 分支运行 v0.11.0 的运营商应进行升级。

强烈建议进行升级，以增强安全性、提升运维可靠性并统一 API 与文档。此版本不包含共识分叉，也不涉及新的 SQL 迁移。区块和交易序列化、签名、代表排序、奖励、费用、激活高度及槽位时序均与 v0.10.2 保持一致。但此版本包含破坏性的 HTTP API 变更，请务必先阅读升级指南：https://docs.adamant.im/own-node/upgrading.html

## v0.11.1 新增功能

v0.11.0 发布时存在一个回归问题：实时对等节点对象缺少 `syncProtocol`，导致 WebSocket 客户端的 `peers.list({ syncProtocol: 'http' })` 无法返回任何候选节点。节点在每次更新时会记录 `No suitable peers found for WebSocket connections`，且不会建立任何出站 WebSocket 连接。虽然节点仍能通过 HTTP 和入站 WebSocket 进行同步，但通过出站 WebSocket 进行的实时区块和交易推送无法正常工作。现在 `Peer.accept()` 会在实例上设置默认的 `syncProtocol: 'http'` 和 `isBroadcastingViaSocket: false`。回归测试已覆盖 Peer 默认值和精确的 `getRandomPeers()` 查询。

升级指南增加了 v0.11.1 章节及监控注意事项。Ubuntu 25.10 之后的默认 `sudo` (`sudo-rs`) 会拒绝示例 sudoers 文件中的 `Defaults:zabbix !requiretty`，且 Zabbix 包装器和 sudoers 规则中的 nvm 解释器路径必须同步更新。

## 安全性与运营商加固

旧版锻造和 DApp 运行时控制接口已被彻底移除，消除了服务器端代码执行、下载/解压/npm/沙箱路径以及代理信任的 HTTP 锻造控制路由，不再尝试在已弃用的接口上修补身份验证。

现在支持可选的加密代表密码短语。运营商可以通过 `npm run adm-node -- forging encrypt|unlock|lock|status` 使用操作员密码（admnode-enc-v1.，AES-256-GCM 加 async scrypt，N=131072, r=8, p=1）对 `forging.secret` 条目进行加密，同时保持与明文的完全兼容。启用加密密钥的节点可保持完全运行（同步、对等节点、API、内存池），锻造功能则保持锁定，直到通过启动时的 TTY 提示符或仅限所有者使用的本地 Unix 控制套接字（位于 `<checkout>/.run` 下，已验证规范目录链、所有者、权限模式和 inode；绝不通过 argv 或环境变量接受密码）进行解锁。此版本包含 `tools/zabbix/` 固定白名单包装器、sudoers 规则、`UserParameter` 以及 Zabbix 7.0 模板，可输出无身份信息的本地锁定状态 JSON（`loading`、`disabled`、`locked`、`partial`、`unlocked`、`unavailable`）及独立的公共漏块/生产力检查。

生产环境反滥用限制现已默认启用。基于 IP（IPv6 /56 分组）的聚合和路由类上限在 60 秒窗口内运行：公共 REST `/api/*`（聚合 15300；状态：12000，读取：3000，发布：300，不含 CORS OPTIONS 预检）和对等节点 HTTP `/peer/*`（聚合 44000；状态：20000，同步：12000，广播：12000，包含固定的 HTTP 429 和 `X-Adamant-Rate-Limit: 1` 协商，以便升级后的对等节点在不被封禁的情况下平滑限流）。在 v0.11.0 中，省略 `X-Adamant-Rate-Limit: 1` 的 `/peer/*` 请求会跳过硬性限制和减速，确保旧版 v0.10.x 对等节点在升级期间不会被驱逐。由于调用方控制该标头，省略它的恶意客户端在 `/peer/*` 上不会受到节点内限流（包括 `GET /peer/blocks`）；运营商应在反向代理或防火墙上对 `/peer/*` 强制执行外部速率限制。客户端 WebSocket (`wsClient.limits`) 的活动/挂起连接池、连接尝试窗口、每个套接字的地址/类型/聊天子类型上限以及订阅速率窗口均已强制执行，同时还包括节点 WebSocket (`wsNode`) 的每个 IP 和每个 nonce 的握手上限。

安装和修复脚本已得到强化。共享辅助工具已提取至 `tools/lib/adamant_node_common.sh`，并具备单元测试覆盖率和 CI ShellCheck 代码检查。脚本生成的 PM2 生态文件包含 `kill_timeout: 120000` 和绝对路径的 nvm 解释器；除非传入 `-f` 参数，否则拒绝重启正在同步/加载/重建的节点；并安装 systemd 插入式配置（`After=`/`Wants=` PostgreSQL 和 Redis，`TimeoutStopSec=180`，`LimitCORE=0`）。脚本要求在恢复快照前进行独立且可信的 SHA-256 验证和 `gzip --test`；`fix_node.sh` 默认在删除数据库前验证快照（使用 `-d` 可显式强制删除）；并使用 `npm ci --omit=dev` 安装依赖，同时锁定 npm/PM2/logrotate 版本。

依赖项已在 7 天发布期隔离后进行了刷新。此版本增加了 `.npmrc` `min-release-age=7`，并在 CI 中通过 `scripts/checkDependencyQuarantine.js` 对根目录 `package-lock.json` 和 `docs/package-lock.json` 进行强制执行。已记录经过审查的 `allowScripts`（`libpq@1.11.0: true`，`javascript-obfuscator: false`），且依赖项刷新后审计结果为 0 中/高/严重漏洞（仅在锁定的 `bitcore-mnemonic`/`bitcore-lib`/`elliptic` 中保留 3 个现有的低危漏洞）。

## API 和 WebSocket 更新

状态、聊天和聊天室过滤器的准确性得到了提升。`and:` 前缀的过滤器已实现清晰映射，`/api/states/get` 和 `/api/chats/get` 上强制执行 `toHeight` (`b_height <= toHeight`)，修复了组合发送者/接收者/参与者过滤器时的共享 SQL 占位符错误，`keysIds` 重命名为 `keyIds` 并增加了 20 字符 KVS `key` 验证，不支持的 `or:` 和未应用的字段现在会被拒绝。

引入了标准化的 `429 Too Many Requests` 契约，返回 `{"success": false, "error": "..."}`，包含 `Retry-After`、标准 `RateLimit-*` 标头（包括 `RateLimit-Scope`）、可选的旧版 `X-RateLimit-*` 以及 CORS 暴露。

出站 WebSocket 对等节点轮换修复在轮换/重新初始化期间拆除出站 WS 对等套接字之前，将 `syncProtocol` 重置为 `http`，从而确保 `connectedPeers` 不会耗尽其候选池。

## 节点可靠性、数据库与对等网络

出站对等节点健康检查和传输响应限制现已设定边界。每个周期的探测目标受到限制（`maxProbeTargets: 20`, `unverifiedProbeLimit: 5`），包括并发数（`updateConcurrency: 8`）、间隔（`probeSpacingMs: 50`）和对等表大小（`maxPeers: 500`）。在网络错误时应用指数退避（30 秒至 1 小时），且不可达的非种子节点在连续 6 次失败后会被驱逐（尊重 24 小时宽限期和 `minConnectedPeers: 10`）。出站对等节点响应上限针对每个端点进行限制，以覆盖 JSON 最坏情况下的扩展（`/peer/blocks` 为 256 MiB，`/peer/transactions` 为 32 MiB，`/peer/signatures` 为 2 MiB，`/peer/list` 为 256 KiB，状态/广播确认为 64 KiB），且不会因同步上限错误而驱逐对等节点。流式 `sync` 请求允许 `/peer/blocks` 的最大响应时间为 `max(peers.options.timeout, 270000)` 毫秒（略低于 `constants.syncStallTimeout`），其他 `sync` 端点为 `max(peers.options.timeout, 60000)` 毫秒，仅在活动流式截止日期中止时推迟 `sync` 范围 30 秒，而不触发全局网络故障退避，同时保留 `peers.options.timeout` 作为套接字不活动超时和状态/广播截止日期。

PostgreSQL 连接恢复功能得到改进。连接失败的客户端被标记为致命错误，以便 `pg-promise` 关闭并替换它们。记录空闲池断开连接，并增加了 10 秒的 `connectionTimeoutMillis`、纯 JS TCP keepalive、`idleTimeoutMillis` 映射以及迁移后的 300 秒 `query_timeout`，防止断开的数据库连接阻塞 `sequence`。

内存检查点守卫查询通过将完整的账户到区块连接替换为高度受限的 `getSlotAccountsBlockAboveHeight(slot)` 进行了优化，该查询仅扫描检查点高度以上的区块。默认种子节点已更新，将主网和测试网引导对等节点列表指向重新定位的活动初始化节点，并更正了 `138.201.152.191` 的端口为 `43998`。

## 协议、共识与轮次结算

增加了高度受限的 `summedRound` 和对齐的回滚奖励索引。在 `sql/rounds.js#summedRound` 中添加了查询 `AND b.height <= ${height}`（由 `modules/rounds.js#sumRound` 传递），确保从高度 1 开始的创世重放不会在高度 101 之前过早结算已持久化区块 2..101 的费用/奖励。修复了 `logic/round.js#applyRound` 回滚 (`backwards === true`) 的问题，将每个代表直接与其对应的 `roundChanges.at(i)` 条目配对，而不改变 `scope.roundDelegates`，防止在混合奖励里程碑轮次回滚期间出现奖励扣除不匹配。在规范主网和测试网上，通过从高度 1 开始的完整重建、镜像启动和检查点恢复，验证了位对位的状态等效性。一个预先存在的关于活跃前 101 名代表排名在轮次边界发生变化时的 `backwardTick` 外部人员 / `votesWeight` 回滚缺陷仍保留在 #300 中跟踪。

不存在共识分叉，也没有新的 SQL 迁移。交易/区块序列化、签名、代表排名、奖励、费用、激活高度及持久化数据库架构与 v0.10.2 保持一致。

## 文档与 OpenAPI 整合

VitePress 文档和 OpenAPI 3.2 规范已直接整合到 `Adamant-im/adamant` 仓库的 `docs/` 和 `openapi/` 目录中，实现了代码、架构和文档的原子化更新。所有文档/OpenAPI 工具（`vitepress`, `@redocly/cli`, `swagger-ui-dist`）均已隔离在 `docs/package.json`、`docs/package-lock.json` 和 `docs/.npmrc` (`min-release-age=7`) 中，保持根目录 `package.json` 的整洁。GitHub Actions 工作流从 master 分支构建并部署统一的 GitHub Pages 站点 (https://docs.adamant.im/ 和 https://docs.adamant.im/schema/ 以及 `schema.json`)，CI 强制验证针对 master 的 PR 中 `openapi/specification/openapi.yaml` 的 `info.version` 与根目录 `package.json` 的 `version` 是否匹配。所有运营商/API 文档和 50 个 OpenAPI 操作已针对 v0.11.0 更新，并新增了 `own-node/upgrading.md`、`own-node/security.md`、`own-node/monitoring.md` 和 `own-node/testing.md`，同时精简了 `README.md`、`.github/CONTRIBUTING.md`、`tools/zabbix/README.md`、`AGENTS.md` 和 `AI_AGENT_NOTES.md`。下游消费者 `Adamant-im/adamant-api-jsclient` 和 `Adamant-im/adamant-console` 将在后续工作中更新，以从 `Adamant-im/adamant/openapi/` 拉取 OpenAPI 源。

## 运营商升级注意事项

部署前将 Node.js 升级至 `22.22.2+` (22.x 版本) 或 `24.15.0+`。优雅地停止正在运行的节点（SIGINT/SIGTERM 并等待 `Cleaned up successfully` — 切勿使用 `kill -9`）。严格从锁文件安装生产依赖：

```
npm ci --omit=dev
```

检查 `config.json` 并删除包含 `max: 0` 的旧版 `api.options.limits` 和 `peers.options.limits` 块，以继承 v0.11.0 的生产默认值（或设置大于 0 的显式 `limit` 值）。仅当节点完全通过一个覆盖 `X-Forwarded-For` 的直接反向代理访问时，才验证 `trustProxy` 是否为 `true`。删除任何调用已停用锻造或 DApp HTTP 控制路由的自动化脚本；通过 `forging.secret` 和优雅重启来管理锻造（并可选择使用 `npm run adm-node -- forging encrypt` 加密密钥，确保 checkout 目录不可被组/其他用户写入，并配置本地 Zabbix 锁定状态监控）。如果您使用加密的代表密码短语，请在每次重启后解锁锻造：

```
npm run adm-node -- forging unlock
```

v0.11.x 不引入新的数据库迁移。重启后，验证 `/api/node/status`、对等节点连接性、反滥用限制，以及（如果使用加密密钥）`npm run adm-node -- forging status --json`。

## 生产环境验证

在此版本发布前，v0.11.0 已在运行 4 个使用加密密码短语的锻造代表的主网节点（Ubuntu 26.04, Node.js 24.22.3, PM2）上运行，通过优雅的目录交换从 v0.10.3 升级。在 16 小时以上的时间里，共锻造了 471 个区块，重启后无漏块，高度与网络同步，除了一次缓慢的轮次节拍后约 30 秒的追赶期间出现广泛哈希共识拒绝外，没有出现 `ERR` 条目（安全检查在落后时拒绝锻造；未丢失任何区块）。加密锻造已进行端到端验证：`forging encrypt` 后进行优雅重启，并在仍处于 `loading` 状态时通过控制套接字进行 `forging unlock`；Zabbix 锁定状态模板和独立的代表结果主机均已验证。v0.11.0 唯一特定的警告是 v0.11.1 中修复的出站 WebSocket 回归问题。

### 破坏性变更

完整运营商迁移指南：https://docs.adamant.im/own-node/upgrading.html

旧版锻造和 DApp 运行时控制 API 已被移除 (#295, GHSA-vjhq-r5fg-85cx)。旧版锻造 HTTP 控制路由（`enable`、`disable`、`status`、`enableAll`、`disableAll`）以及旧版 DApp 运行时/执行/签名/对等路由（安装、启动、停止、卸载、状态检查、服务器端签名/提现、动态 DApp 路由和 DApp 对等运行时路由）均已移除。锻造现在仅通过 `config.json` 中的 `forging.secret` 进行配置（更改时需优雅重启），并在使用加密密码短语时通过可选的本地 `adm-node` CLI 进行解锁/锁定。旧版 `forging.access` (`whiteList`) 和 `dapp` 配置块仍可加载以兼容升级，但会被忽略并记录启动弃用警告。只读 DApp API 和 DApp 交易类型 5、6 和 7 的共识处理保持不变；客户端必须在本地签署交易并通过标准交易端点（`POST /api/transactions` / `POST /api/transactions/process`）提交。

现在在状态、聊天和聊天室上强制执行严格的 `and:` 过滤验证 (#294)。在 `/api/states/get` (GET 和 POST)、`/api/chats/get` 和 `/api/chatrooms/*` 上，`and:` 前缀的过滤器被规范化为普通字段名并严格通过 AND 组合。`or:` 前缀的过滤器现在会被拒绝（`OR filters are not supported`），而不是被静默忽略。之前未应用或拼写错误的参数（包括 `fromHeight`/`toHeight` 和 `/api/chatrooms/*` 上的查询 `userId`、`blockId`、时间戳/金额/费用过滤器、`minConfirmations` 以及拼写错误的 `keysIds`）现在会被拒绝；状态批量键查找已重命名为 `keysIds` 到 `keyIds`，使用 20 字符的 KVS `key` 格式。冲突的普通值和 `and:` 前缀值也会被拒绝。

最低 Node.js 版本已提高 (#296)。所需的运行时现在为 `^22.22.2 || >=24.15.0`（之前为 `>=22.13.0`）。Node.js `24.0.0–24.14.x` 不支持开发工具链。

生产环境反滥用限制默认启用 (#292)。`config.default.json` 现在启用非零 HTTP 和 WebSocket 速率限制。包含 `api.options.limits` 或 `peers.options.limits` 下旧版 `max: 0` 的现有 `config.json` 文件将保持该接口禁用并记录启动警告；运营商应删除这些块以继承 v0.11.0 的默认值或配置大于 0 的显式 `limit` 值。
