去中心化通信依赖于独立运行的节点来验证、交换和保存数据。ADAMANT 节点 v0.11.1 是一个侧重于安全性和可靠性的版本，在保持协议现有共识规则不变的前提下，增强了日常运维能力。这是 v0.11 系列的第一个标记版本；v0.11.0 代码虽已合并但未打标签，而 v0.11.1 包含了一个额外的对等网络修复，因此已运行该代码的运营商应进行升级。

### 减少攻击面

此版本移除了旧版的 HTTP 伪造控制和 DApp 运行时端点。这些接口包含服务器端执行和签名路径，已不再适用于现代节点。移除这些接口解决了 GHSA-vjhq-r5fg-85cx 安全公告中提到的问题，并使节点的运维边界更加清晰。代表现在通过 `forging.secret` 配置伪造，并通过优雅重启应用更改。可选的本地 CLI 命令可用于解锁和锁定加密的密码短语。只读的 DApp API 以及针对现有 DApp 交易类型的共识处理功能保持不变；客户端应在本地对交易进行签名，并通过标准交易端点提交。

### 加密代表密钥

运营商现在可以使用 AES-256-GCM 和 scrypt 通过运营商密码对伪造密码短语进行加密。明文配置对于现有部署仍然兼容。带有加密密钥的节点在伪造功能锁定期间，仍可进行同步、维护对等节点、提供 API 服务以及处理内存池。每次重启后，运营商通过本地提示符或仅限所有者访问的 Unix 控制套接字解锁伪造功能。监控支持允许运营商在不暴露代表身份的情况下观察锁定状态。加密保护了存储的密码短语，但并未免除运营商保护主机、密码、备份和访问权限的责任。

### 网络稳健性

生产环境的 HTTP 和 WebSocket 反滥用限制现已默认启用，涵盖公共 API、对等流量、连接尝试和订阅，并为受限请求提供记录在案的 HTTP 429 响应。存在一个重要的混合版本注意事项：在过渡期间，不发送速率限制协商标头的旧版对等节点会绕过节点内的 HTTP 限制。运营商应在反向代理或防火墙上对 `/peer/*` 强制执行外部限制。明确包含旧版 `max: 0` 设置的现有配置将保持相关限制处于禁用状态，直到更新为止。

此版本还限制了对等节点健康检查，更审慎地处理无法访问的对等节点，并改进了连接丢失后的 PostgreSQL 恢复机制。安装和修复脚本现在会在默认数据库替换路径之前验证快照，使用基于锁文件的依赖安装，并在节点同步或重建时更加谨慎地执行重启。

### 恢复实时对等连接

v0.11.1 的最终修复恢复了出站 WebSocket 对等节点的选择。在未打标签的 v0.11.0 代码中，由于实时对等对象缺少默认值，导致候选查询无法返回任何对等节点。节点虽然仍能通过 HTTP 同步并接收入站 WebSocket 连接，但出站的实时区块和交易推送无法工作。此修复在实时对等实例上设置了默认值，并且回归测试涵盖了对等默认值和选择查询。

### 重放正确性与更严格的 API

轮次结算现在在重放期间遵循当前的区块高度，回滚奖励索引将每个代表与其自身的变化对齐。发行说明报告了在完整重建、镜像启动和检查点恢复过程中，主网和测试网上的逐位状态等效性检查结果。一个先前存在的回滚问题仍记录在 issue #300 中。

对于应用程序开发者而言，针对状态、聊天和聊天室的过滤器处理变得更加严格。支持的 `and:` 过滤器被一致应用；不支持的 `or:` 过滤器和先前被忽略的参数将被拒绝。批量键参数从 `keysIds` 更改为 `keyIds`。这些是有意为之的破坏性 HTTP API 变更，因此在部署前应检查相关集成。

### 统一文档

节点文档和 OpenAPI 3.2 规范现在与节点仓库中的代码存放在一起，从而能够同步更新行为、文档和 API 契约。运营商和开发者可以浏览统一的 [文档](https://docs.adamant.im/) 和 [API 架构](https://docs.adamant.im/schema/)，其中包括关于升级、安全、监控和测试的最新指南。

### 升级注意事项

此次升级不引入共识分叉，也不涉及新的 SQL 迁移。区块和交易序列化、签名、代表排序、奖励、费用、激活高度和时隙计时与 v0.10.2 相比保持不变。升级需要注意运维和 HTTP API 的兼容性。运营商应阅读 [升级指南](https://docs.adamant.im/own-node/upgrading.html) 并检查集成中是否存在已移除的路由和更严格的过滤器。需要支持的 Node.js 版本：`^22.22.2 || >=24.15.0`。请优雅地停止节点并等待清理，然后在重启前检查速率限制、代理信任和伪造配置。如果伪造密钥已加密，请在每次重启后解锁并验证本地锁定状态。升级后，请检查节点状态、对等连接和反滥用设置。
