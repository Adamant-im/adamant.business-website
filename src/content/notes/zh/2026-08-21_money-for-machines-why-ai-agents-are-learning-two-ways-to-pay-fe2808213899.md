随着自主智能体开始代表个人和公司进行购物、订阅和结算发票，支付行业正在重新审视一个古老的争论——许可信任与无需许可的代码——并逐笔交易地进行实践。

在过去十八个月里的某个时间点，结账柜台出现了一位奇怪的新顾客。它没有面孔，没有实体钱包里的银行卡，也没有耐心去处理验证码（CAPTCHA）。它是一个 AI 智能体——即代表个人或公司执行操作的软件——它想要支付某些费用：API 调用、数据集、订阅续费，或是被要求重新预订的航班。麦肯锡估计，到 2030 年，仅在美国，智能体可能就将负责高达 1 万亿美元的交易额。直到最近，人们才完全回答了一个既平凡又巨大的问题：*一段软件代码究竟该如何支付？*

两个行业几乎同时从相反的方向给出了答案。信用卡网络和金融科技巨头在不触动底层轨道的情况下，围绕智能体重新构建了结账流程。而加密货币行业则专门构建了新的轨道，因为旧轨道并不适合软件。这两种方案目前都在运行，都在增长，且谁也没有“胜出”。相反，出现了一种静默的劳动分工，这比任何单一公司的路线图更能说明机器支付的真实经济学逻辑。

### 房间里的新买家

智能体商业（Agentic commerce）在 2025 年底不再仅仅是一个思想实验。当时，OpenAI、Stripe 和 Meta 发布了智能体商业协议（ACP）作为开放标准，随后 PayPal 也推出了集成方案，允许 ChatGPT 用户无需离开聊天界面即可完成结账。Visa 推出了 Trusted Agent，Mastercard 推出了 Agent Pay——这两者都是允许经过验证的 AI 智能体使用令牌化、受限的凭据而非原始卡号代表消费者进行交易的框架。商业推广始于 2026 年初，最初是在 Mastercard 的少数几个亚洲市场，随后范围进一步扩大。

在基础设施层面，Google 提出了一个互补的组件：AP2，即智能体支付协议（Agent Payments Protocol）。AP2 本身并不转移资金，它将*证明*标准化。其核心是 W3C 可验证凭据：即经过加密签名的记录，说明人类实际授权智能体支付的内容、用途、金额上限以及有效期。与其说它是一种支付轨道，不如说它是一张任何轨道都可以核验的“许可条”。

与此同时，区块链领域也在公众视野下构建了一套平行的技术栈。Coinbase 的 x402 协议——以长期闲置的 HTTP 402 “Payment Required” 状态码命名——允许智能体在单次 HTTP 往返中内联支付 API 响应费用，并以 Base 和 Solana 等低手续费网络上的稳定币进行结算。Stripe 则推出了自己的机器支付协议（MPP），用于基于会话的机器支出。像 Skyfire 这样由 Coinbase Ventures 和 a16z 支持的初创公司，则直接为智能体提供了它们自己的钱包——有的存入 USDC，有的则桥接到传统银行系统。

到 2026 年中期，四种协议实际上已经分工明确：AP2 用于*授权*（“人类真的批准了吗？”），ACP 用于*结账*（“与商家协商购物车”），而 x402 或 MPP 用于*结算*（“实际转移资金”）。今天，一个智能体购买商品时，可能在一次购买中同时接触到这三种协议。

### 路径一：教旧轨道信任机器人

传统金融的方法在结构上是保守的——这正是其核心所在。Visa、Mastercard、PayPal 和 Stripe 并不是要为智能体重新发明货币；他们试图将八十年来积累的信任基础设施——拒付、欺诈责任转移、KYC（了解你的客户）、争议解决、消费者保护法——扩展到一类新的非人类账户持有者身上。根据 ACP 或 Agent Pay 授权的智能体，最终通过人类银行卡所使用的相同轨道进行支出：即交换费、网络规则等。Stripe 发行的令牌或许可以授权购买，但它最终仍通过 Visa、Mastercard 或存档的银行卡进行扣款，并承担 1.5%–3.5% 的标准交换成本。

这种继承性是其全部价值主张所在。如果智能体行为失控、超额支出，或者被提示词注入（prompt-injected）的商家页面欺骗，现有的流程可以弥补人类的损失——因为该轨道从第一天起就是基于“资金转移有时会出错且需要可逆”的假设构建的。PayPal 的智能体服务将其 API 工具包与自有的受监管稳定币 PYUSD 相结合，并在拥有 60 家公司的 AP2 标准组织中占有一席之地——这显然是在同时进行双向对冲。

> 传统轨道对智能体经济的全部推销辞令只有一句话：当出现问题时，我们已经知道该怎么做。

### 路径二：构建从未为人类设计的货币

Web3 的答案始于另一个观察：智能体实际需要支付的大部分费用看起来根本不像人类的购买行为。它看起来更像是一种通行费。一个模型调用另一个模型的 API，一个爬虫按页面付费，一个研究型智能体为每次数据集查询支付几分钱——这些都是高频、低值、机器速度的交易，而信用卡系统的经济模型从未为此而生。当购买的商品仅值两分钱时，设置 30 美分的固定处理费底线是毫无意义的。

区块链轨道上的稳定币几乎是偶然地填补了这一空白。在 Base 等 Rollup 上的结算成本仅为几分钱的一小部分——通常被引述为约 0.0001 美元——且在几秒钟内即可完成最终确认，无需预先开立账户。加密流动性公司 Keyrock 在 2026 年 5 月发布并被 CoinDesk 报道的一份报告显示，AI 智能体已经在加密轨道上完成了 1.76 亿笔交易，结算金额达 7300 万美元，其中约四分之三的支付额度低于信用卡支付不再具备经济效益的固定费用底线——仅 USDC 就占了总交易量的 98.6%。这并非假设性的未来市场；从数据来看，它已经成为特定、狭窄且高频支出类别的默认机器支付层。

关于加密轨道，还有一个较少被讨论的论点，即架构而非经济层面的：可编程性。稳定币支付可以携带逻辑——如托管条件、多智能体收入分成、交付确认后自动释放——直接嵌入交易本身，无需第三方平台来调解规则。对于智能体之间的商业活动，如果双方都不是银行客户，且都不想将对方引入专有平台，那么这种组合性（composability）可以说比节省成本更有价值。

> 信用卡轨道是为了让人类信任商家而构建的。稳定币轨道则是为了让两段软件代码除了数学之外无需信任任何事物而构建的。

### 为什么这并非真正的“Web3 对抗银行”

如果将其描述为一场竞争，那么这个故事是不完整的，因为构建这些轨道的公司一直在拒绝选边站。Visa 正在推行所谓的“双轨战略”——即在卡网络上使用 Trusted Agent 令牌，同时进行稳定币结算试点。PayPal 同时提供基于卡的智能体工具包和 PYUSD。即使是 Coinbase 的 x402（其中最原生于加密货币的协议），也被设计为接入 Google 为卡世界构建的同一个 AP2 授权层，这正是为了确保“谁批准了这笔支出”的问题不必在每条轨道上重复解决。

![机器之财：AI 智能体为何正在学习两种支付方式](/images/engineering-notes/medium/fe2808213899/002-7e415e449d.webp)

更准确的框架是，智能体正在默认成为“多轨道”使用者，且轨道是按交易而非按智能体来选择的。一次性、高价值的消费者购买行为——如机票、家具——仍然倾向于信用卡轨道，因为交换成本只是四舍五入的误差，且由于错误代价高昂，可逆性至关重要。而每天重复一万次的机器对机器 API 调用则倾向于稳定币，因为那里不需要可逆性，且 2% 的手续费会使整个产品模式无法生存。从已知的、经过 KYC 认证的品牌商家处购买倾向于传统方式，因为围绕该商家的法律和声誉基础设施已经存在。向从未交易过的匿名智能体支付——即真正的智能体对智能体经济——则倾向于加密货币，因为没有共享的银行关系可供依赖，只有双方都能独立验证的协议。此外，跨境、全天候的机器商业不会等待营业时间或代理行处理；稳定币可以全天候结算，而国内面向消费者的商业大多并不需要这种特性。

这正是传统金融本身所预言的模式。信用卡在消费者零售领域胜出，是因为消费者对可逆性和争议保护的需求超过了对速度的需求。电汇和 ACH 在大型 B2B 支付中胜出，是因为双方已经互相信任，且比起即时最终性，他们更关心成本。智能体只是在加速这种细分过程，并将其公开化，因为软件使权衡变得明确，而人类的习惯通常会掩盖这一点。

### 尚未解决的部分

两条路径都在超越旨在约束它们的护栏，而行业内部的风险团队对此深有体会。

在传统方面，银行安全研究人员越来越多地将智能体 AI 描述为引入了“一个无法完全契合现有银行模型的第三方参与者”——软件在跨机构边界做出决策并执行交易，有时其方式是底层客户从未明确授权的。欺诈损失已经以每年约 20% 的速度增长，而合成身份欺诈——即生成式 AI 融合真实与虚构的身份数据——据报道在 2026 年达到了转折点。监管机构尚未跟上：在美国，OCC 修订后的模型风险管理指南明确将生成式和智能体 AI 模型排除在其范围之外，这意味着银行几十年来依赖的治理手册尚未扩展到他们现在正在部署的技术上。

在加密方面，同样的不成熟表现得有所不同。不可逆性这一使微支付具备经济可行性的特性，也是导致受损智能体钱包造成灾难性后果的缺陷——攻击者一旦获取私钥，就无法进行拒付。智能体身份目前大多只是一个钱包地址，而非法律上的责任主体，这留下了一个悬而未决的问题——对于商家、监管机构或受害者而言，当自主智能体进行不良交易时，究竟由谁承担责任？此外，2026 年为稳定币带来秩序的监管框架——美国的《GENIUS 法案》、欧洲的 MiCA、欧盟的《AI 法案》——在起草时都是以人类发起的交易为考量的。它们都没有直接解决自主的机器对机器支付问题，也没有在没有人类点击“购买”时分配责任。

换句话说，两条轨道都被要求承载它们最初并未设计用来承载的自主决策量——前者是因为其信任模型假设人类最终负责，后者是因为其结算模型假设最终性总是可取的。

### 这在实践中意味着什么

对于任何正在构建智能体可能与之交互的产品（如 API、店面、订阅产品）的企业来说，实际的启示不是“选择加密货币”还是“选择信用卡”。而是要确保你的产品能够以一种“轨道无关”的方式进行*计量和授权*：公开机器可读的定价，支持受限的、有时效的授权而非静态的 API 密钥，并且不要假设支付方是浏览器另一端持卡的真人。协议将继续整合——没有人会认真认为四五个相互竞争的智能体支付标准能存活十年——但核心需求，即一个能够证明其被允许支出多少金额，并能以交易实际规模廉价结算的机器，这一需求是不会消失的。

更值得关注的长远问题不是哪条轨道会胜出。而是当大多数交易不再涉及人类的决策时刻时，交易的“意义”会发生什么变化——当“我买了它”悄然变成“我授权的一个智能体，在三个环节之外，为我买了它”。支付基础设施花了一个世纪的时间来优化人类决定消费的那一刻。现在，它正在实时重建，以适应人类仅仅*允许*消费——并将决定权交给其他事物的那一刻。
