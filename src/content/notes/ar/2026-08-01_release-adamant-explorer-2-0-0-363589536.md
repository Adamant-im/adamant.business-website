يُعد ADAMANT Explorer v2.0.0 أول إصدار مستقر منذ v1.3.0. يعمل هذا الإصدار على تحديث واجهة Explorer الأمامية والخلفية، ونظام المراقبة الحية، ومعايير الأمان، والتبعيات، والاختبارات، والوثائق التشغيلية، مع الحفاظ على روابط الصفحات العامة والروابط العميقة الحالية.

تمت إعادة بناء الواجهة الأمامية باستخدام Vue 3 و Pinia و Vue Router 5 و Vite 8، لتحل محل حزمة AngularJS و Bootstrap 3 و Webpack السابقة. تتميز الآن جميع صفحات Explorer العامة بتصميمات متجاوبة لأجهزة سطح المكتب والأجهزة اللوحية والهواتف المحمولة، مع سمات فاتحة وداكنة ثابتة، وعناصر تحكم يسهل الوصول إليها، وبطاقات معاملات مخصصة للهواتف، وتلميحات أدوات أكثر أماناً، وتحسينات في ميزة نسخ البيانات. كما تمت إضافة دلالات سياقية للمعاملات تشمل التحويلات، وعمليات التصويت وإلغائه، وعمليات DApp، ونشاطات المنصات، ومكافآت الترحيب.

على مستوى الواجهة الخلفية، تمت إعادة بناء الوصول إلى ADAMANT Node حول `adamant-api` 3.1.0 مع ميزات التحكم في الجاهزية، وتجاوز الفشل، والترقيم المحدود، وتوحيد الأخطاء، وفصل طبقات الطلب والمعالجة. تم الاحتفاظ بالمسارات الـ 12 ذات الأصل الواحد المطلوبة لواجهة Explorer، وإضافة مسار جديد `GET /api/networkHealth`. كما تم تفعيل التحقق الصارم من المسارات والاستعلامات، وترتيب المعاملات الحتمي، وتصحيح تصفية التحويلات، وترقيم صفحات الحسابات الكبرى، والتأكيدات الحية، وتنسيق ADM بدقة كاملة. أصبح استخدام Redis اختيارياً للخدمات الأساسية، مع الحفاظ على التخزين المؤقت المرن لواجهة برمجة التطبيقات وإحصائيات الكتل والأقران المتجددة.

تم استقرار نظام المراقبة الحية عبر دورات حياة Header و Delegate Monitor و Network Monitor و Activity Graph Socket.IO مع تفعيل الاستطلاع المتسلسل وإعادة المحاولة المحدودة. تمت إضافة تحديثات الصفحات المعتمدة على الكتل وتأكيدات REST المحدودة لإشعارات الكتل عبر WebSocket. كما تم تحسين جداول المندوبين، وحالات التعدين، والمكافآت، والرسوم، وإحصائيات الأقران، وترتيب الإصدارات، وسلوك حدود الجولات. تم استبدال تكامل Freegeoip بخيار تحديد الموقع الجغرافي للأقران عبر GeoJS، مع تقديم وكيل بلاطات OpenStreetMap محلي، ومُتحقق منه، ومخزن مؤقتاً، ومحدد المعدل.

تشمل تحسينات الأمان والموثوقية إزالة wildcard CORS و16 نقطة نهاية لواجهة برمجة تطبيقات Explorer القديمة وغير المدعومة. تمت إضافة تحديد معدل الطلبات الواعي بالوكيل، والوكلاء الموثوقون، ورؤوس الأمان، و CSP مقيد، وأخطاء مستقرة، ومهلات HTTP صريحة. تم تقليل سجلات الطلبات باستبعاد سلاسل الاستعلام، كما يتم التحقق من بيانات Node والأقران والوكيل و Redis والموقع الجغرافي وأصل المتصفح غير الموثوقة. تمت إضافة نموذج تهديدات للمستودع، ومراجعة للأمان والموثوقية، وتغطية اختبارات وحدة واسعة النطاق للحدود العامة وحالة المراقبة الحية.

تم تحديث بيئة التشغيل المدعومة إلى Node.js `^22.18.0 || >=24.11.0`. كما تم تحديث Express و Redis و Socket.IO و Axios و Vue و Vite و Pinia و Vue Router و ESLint و Mocha و Chai و Supertest والتبعيات المتبقية. تمت إزالة Grunt و Protractor و Cucumber و Jenkins و Travis و Webpack/Babel القديمة، بالإضافة إلى تكاملات Market Watcher والمنصات المهملة. تمت إضافة 43 وحدة اختبار وحدة خاصة بـ Node، وتحديث تركيبات Testnet الحية، وتوسيع تغطية واجهة برمجة التطبيقات، والأمان، والجدولة، وتشكيل البيانات، وأدوات الواجهة الأمامية. تم تحديث `README.md` بأدلة تشغيل المساهمين ووكلاء الذكاء الاصطناعي الحالية.

شملت عمليات التحقق اجتياز اختبارات ESLint و Prettier، وبناء نسخة إنتاجية تتضمن 6,337 وحدة، ومجموعة اختبارات وحدة تضم 226 اختباراً، ومجموعة اختبارات واجهة برمجة تطبيقات Testnet حية تضم 41 اختباراً على شجرة المصدر المُصدرة، وتدقيق تبعيات أظهر 0 ثغرات أمنية، واختبارات متصفح غطت 13 مساراً على دقات شاشة سطح المكتب والجهاز اللوحي والهاتف المحمول دون أخطاء في وحدة التحكم أو تجاوز أفقي.

### تغييرات جذرية

يجب ترقية Node.js إلى `^22.18.0 || >=24.11.0`. يجب إنشاء تكوين النشر من ملف `config.default.jsonc` الجديد، مع مراجعة `nodes_adm` و `trustedProxies` و `redis` و `geoLocation` و `exchangeRates` و `log_level`. يلزم وجود ADAMANT Node v0.10.2 أو أحدث، ويفضل استخدام عقد HTTPS متعددة يتم تشغيلها بشكل مستقل. يجب استبدال تكامل Freegeoip الذي تمت إزالته بتكوين GeoJS الاختياري؛ حيث يؤدي تعطيل تحديد الموقع الجغرافي إلى إبقاء بيانات الأقران وأسماء المضيفين متاحة دون خرائط أو أعلام دول. يجب على المستهلكين الخارجيين لمسارات واجهة برمجة تطبيقات Explorer التي تمت إزالتها الانتقال إلى `adamant-api-jsclient`، ويجب استخدام `GET /api/networkHealth` للمراقبة التشغيلية. يجب السماح بمسار `/osm-tiles/` ذو الأصل الواحد في قواعد الوكيل العكسي وجدار الحماية. يجب بناء حزمة `public/` التي يتم تجاهلها أثناء النشر باستخدام `npm run build`. للتطوير، استخدم `npm run dev` لحزمة الواجهة الخلفية و Vite المدمجة أو `npm run dev:frontend` لـ Vite فقط. تظل مسارات صفحات Explorer الحالية والروابط العميقة متوافقة، ويوصى باستخدام Redis ولكنه لم يعد مطلوباً لخدمات HTTP الأساسية والثابتة.
