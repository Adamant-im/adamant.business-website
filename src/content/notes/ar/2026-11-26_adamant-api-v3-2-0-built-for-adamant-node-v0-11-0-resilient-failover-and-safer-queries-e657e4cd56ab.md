تقدم cryptofoundry ملخصاً لإصدار adamant-api v3.2.0، وهو حزمة تطوير البرمجيات (SDK) الرسمية بلغة TypeScript وNode.js الخاصة بـ ADAMANT، والتي تم تنسيقها لتتوافق مع ADAMANT Node v0.11.0.

إن بناء تطبيقات لامركزية، أو روبوتات تداول، أو مستكشفات، أو تكاملات دفع مباشرة مقابل نقاط نهاية HTTP الخام للبلوكشين يعني إعادة ابتكار نفس آليات الموثوقية والتشفير مراراً وتكراراً: اختيار العقد المتزامنة، وإعادة محاولة العمليات عند انقطاع الاتصال المؤقت دون تكرار المعاملات، وتشفير الرسائل باستخدام NaCl، وتوقيع المعاملات الحتمية، ومزامنة كائنات نقل البيانات (DTOs) الخاصة بـ TypeScript مع ترقيات العقد. توفر حزمة SDK هذه الحلول جاهزة للاستخدام مع مرونة فائقة دون الحاجة إلى كتابة تعليمات برمجية إضافية (حيث يمكنك تمرير قائمة من عقد HTTPS التي تعمل بشكل مستقل، لتقوم الحزمة بمراقبة الحالة، والتحقق من ارتفاعات المزامنة، وتخطي العقد القديمة أو التي لا تزال قيد التحميل، وتفعيل خاصية تجاوز الفشل تلقائياً)، بالإضافة إلى دعم استيراد المسارات الفرعية النمطية، وتوفير أمان TypeScript شامل مع DTOs تم إنشاؤها من مواصفات OpenAPI 3.2 المعتمدة لـ ADAMANT Node، واشتراكات Socket.IO المباشرة مع استعادة تلقائية للاتصال.

### التحقق من المفتاح العام للمستلم والمندوب محلياً

قبل تشفير أي رسالة أو التصويت لمندوب، يقوم الإصدار v3.2.0 بالتحقق محلياً من أن كل مفتاح عام Ed25519 يتم إرجاعه بواسطة العقدة هو مفتاح قانوني مكون من 32 بايت، يقع على المنحنى، وغير ذي رتبة صغيرة، كما يقوم باشتقاق عنوان ADM المطلوب تشفيرياً. يتم رفض المفاتيح المشوهة، أو التي تقع خارج المنحنى، أو ذات الرتب الصغيرة (الرتب 1، 2، 4، و8)، أو غير المتطابقة بشكل نظيف قبل التخزين المؤقت أو التشفير، كما يتم عزل ذاكرة التخزين المؤقت للمندوبين لكل مثيل من `AdamantApi`.

### إصلاحات أمنية وحرجة لدقة استعلامات KVS والدردشة

في الإصدارين v3.0.0 وv3.1.0، كانت دوال `getKVS()` و`getChatTransactions()` و`getChats()` و`getChatMessages()` ترسل فلاتر مسبوقة بـ `and:`، وهي فلاتر كانت تتجاهلها العقد التي تسبق إصدار v0.11.0 بصمت مع إرجاع `success: true` مع سجلات غير مفلترة. في الإصدار v3.2.0، ترسل هذه الطرق دائماً أسماء فلاتر عادية (مع تبسيط أغلفة `and: { ... }` الصريحة) وترفض أغلفة `and:` غير المدعومة والمفاتيح المسبوقة بروابط من جانب العميل. يجب على كل تطبيق يستخدم الإصدار 3.x لقراءة بيانات KVS أو الدردشة الترقية إلى v3.2.0.

### معالجة مرنة لخطأ HTTP 429 في Node v0.11.0

يُفعل ADAMANT Node v0.11.0 حدود الحماية من إساءة الاستخدام لبروتوكولي HTTP وWebSocket بشكل افتراضي. عندما تعيد العقدة خطأ HTTP 429، تتحول عمليات القراءة المتماثلة (مثل GET وPOST `/api/states/get`) فوراً إلى عقدة أخرى متزامنة ومخزنة مؤقتاً، بينما تدخل العقدة المحدودة بمعدل طلبات في فترة تهدئة محددة (تصل إلى 60 ثانية) لضمان عدم توجيه حركة المرور إليها مجدداً عبر فحوصات الحالة. الطلبات المتوازية التي تصل إلى عقدة محدودة تشترك في فحص حالة واحد مكرر بدلاً من إغراق `/api/node/status` أو التبديل المستمر بين العقد النشطة. في إعدادات العقدة الواحدة أو عندما تتجاوز نافذة إعادة تعيين العقدة فترة الانتظار المحددة بـ 10 ثوانٍ في SDK، يكشف `AdamantApiResult` الآن عن حقول اختيارية وهي `status` و`retryAfterMs` و`rateLimitScope` حتى تتمكن الروبوتات من جدولة عمليات إعادة المحاولة بشكل نظيف. لا يتم إعادة تشغيل طلبات POST الخاصة بنشر المعاملات تلقائياً بعد تلقي استجابة HTTP.

### جاهزية أكثر ذكاءً عند بدء التشغيل

كانت الخدمات التي تعمل جنباً إلى جنب مع عقدة محلية تشهد أحياناً إطلاق `onReady` بينما كانت العقدة لا تزال تحمل جداول الذاكرة أو تقوم بمزامنة السلسلة. في الإصدار v3.2.0، يتم استبعاد العقد التي تبلغ عن `loader.loaded: false` أو `loader.syncing: true` من اختيار واجهة برمجة التطبيقات (API) وWebSocket الأساسي. تنتظر `onReady` (و`api.isReady`) مع تراجع تدريجي في إعادة المحاولة عند بدء التشغيل (5 ثوانٍ، 10 ثوانٍ، 30 ثانية، 60 ثانية) حتى تصبح العقدة قابلة للاستخدام فعلياً لخدمة الاستعلامات، وتمتلك العملاء المهيأة خاصية احتياطية للمزامنة مقيدة بالارتفاع في حال تعطل جميع العقد المتزامنة بالكامل.

### استخدام POST /api/states/get وتوافق الأنواع الصارم مع v0.11.0

للاستعلام عن عشرات أو مئات مفاتيح KVS أو عناوين المرسل دون تجاوز حدود طول رابط URL، مرر `{method: 'POST'}` إلى `getKVS()`:

```js
const response = await api.getKVS(
  {
    senderIds: ['U16655734187932477074', 'U15423595369615486571'],
    keyIds: ['eth:address', 'btc:address', 'doge:address'],
    toHeight: 55_000_000,
  },
  {method: 'POST'},
);
```

تعكس واجهات TypeScript الآن (`ChatroomsOptions` و`ChatTransactionsOptions` و`KVSOptions`) التحقق الصارم من الاستعلامات في ADAMANT Node v0.11.0 بحيث يتم اكتشاف الحقول غير المدعومة في وقت التجميع، كما يقوم مولد OpenAPI الآن بالمزامنة مباشرة من `Adamant-im/adamant`.

### أمن سلسلة التوريد وفترة الحجر الصحي لمدة 7 أيام

اتباعاً لسياسة الأمان الخاصة بـ ADAMANT التي تم تقديمها في Node v0.11.0، تفرض adamant-api الآن فترة حجر صحي لإصدارات البرامج مدتها 7 أيام (`minimumReleaseAge: 10080` في `pnpm-workspace.yaml`)، وتقيد نصوص دورة حياة التبعيات عبر `allowBuilds`، وتأتي مع صفر ثغرات أمنية في `pnpm audit` للإنتاج، وتُنشر على npm مع إثبات المصدر الموثوق عبر GitHub Actions.

```
npm install adamant-api@3.2.0
```
